# Solidity / Foundry

- When integrating upstream contracts pinned to older solc versions than the project's, do not import their sources across versions; deploy their compiled bytecode and interact through version-independent interfaces/ABIs. Confidence: 0.85
- When writing ABI interfaces to match a vendored upstream contract, verify the actual function signatures/types against the upstream source — a wrong param type (e.g. `uint256` vs `int256`) silently changes the selector and causes opaque reverts. Confidence: 0.85
- Size test positions/liquidity realistically (avoid degenerate values like L=1 that make fees round outputs to zero); pick values that produce meaningful positive outputs. Confidence: 0.8
- Keep upstream license files intact when vendoring; correct any plan/license assumptions to match the true upstream license. Confidence: 0.7
- When a task spec locks an ABI (enum/struct/function signatures), implement exactly that ABI; do not invent or add functions beyond it. Confidence: 0.65
- Validate/allowlist external contract addresses (pools/factories) before calling them; never trust user-supplied addresses and never auto-allowlist (deploy scripts take factories from env placeholders and skip admin calls when empty). Confidence: 0.78
- Validate ported quote math (e.g., Rust) against the on-chain Solidity reference via Foundry fixtures or forge probes — aim for byte-exact matches with on-chain output, not just self-consistent results. Confidence: 0.7
- When hand-writing EVM ABI calldata encoders, pin keccak function selectors in unit tests and decode the FULL nested structure (head, dynamic arrays, element offsets) in integration tests — argument offsets exclude the 4-byte selector and dynamic-array element offsets are relative to the start of the element-offset list, so prefix-only assertions miss the classic two-level offset bug. Confidence: 0.75
- Normalize EVM addresses to lowercase at the ingestion/graph boundary: RPC-sourced addresses are lowercase, and mixed-case constants (e.g., an ERC-20 in a test fixture) cause silent lookup mismatches against the graph. Confidence: 0.7
- Extend on-chain enums append-only (e.g. `DexType.Xylo = 3`), never insert new values in the middle — ABI-encoded enum values must stay stable across redeploys. Confidence: 0.8
- When porting upstream Solidity math, preserve the exact statement order and intermediate divisions (e.g. Xylo `_getY`'s sequential `c` accumulation with `A_PRECISION` applied per statement): reordering multiplications/divisions shifts intermediate rounding and breaks byte-exact vector matches. Confidence: 0.7
- Test ERC-20 mocks must enforce real allowance/balance semantics (revert on insufficient allowance, track spending) so approval bugs surface in Foundry tests instead of passing and reverting only on-chain. Confidence: 0.7tics: during CREATE the constructor's `msg.sender` is the deployed contract itself (not the factory), so the factory must forward seed balances after deployment — mocks that ignore this diverge from on-chain behavior. Confidence: 0.6
- Simulate before broadcasting irreversible on-chain operations: dry-run a forge script (via the operator wrapper, e.g. `--dry-run`) and only `--broadcast --slow` once simulation succeeds — never skip straight to broadcast. Confidence: 0.7
- When a forge-script local simulation is inherently unachievable (e.g. the chain's native token routes through a system precompile that foundry executes natively and stack-underflows, so `vm.mockCall` can't intercept it), don't block on an impossible sim gate: validate against live chain state via `cast estimate`/`cast call` on the target contract, then broadcast with `--skip-simulation`. Confidence: 0.6
- Parity tests for ported venue quote math cover both swap directions and three sizes, pinned against the venue's own view functions (e.g. `getAmountsOut`, `calculateSwap`) rather than a single happy path. Confidence: 0.7
